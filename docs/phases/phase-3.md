# Phase 3 — Courtroom Management & Case Registration

> **Context:** Read `AGENTS.md` first. Phases 0–2 must be complete. Account management, audit logging, and auth should be working.

## What you are building

Registrar can manage courtrooms (create/edit/deactivate) and register new court cases. CIN is auto-generated on case creation. Cases appear in a sortable data table.

## Functional Requirements covered

- **FR5:** Registrar creates a court case with defendant info, crime details.
- **FR6:** System auto-generates a unique CIN.
- **FR7:** Registrar records presiding judge, prosecutor, lawyer, trial dates.
- **FR8:** Courtroom infrastructure (needed for hearing scheduling in Phase 4).

## Tasks

### 3.1 — Courtroom validators
- **File:** `lib/validators/courtroom.ts`
- `createCourtroomSchema`: name (string, min 1), location (string, optional), maxSlots (number, min 1, max 20)

### 3.2 — Courtroom server actions
- **File:** `actions/courtroom.actions.ts`
- `createCourtroom(data)`: role check (REGISTRAR), validate, insert, logAudit
- `updateCourtroom(id, data)`: role check, validate, update, logAudit
- `toggleCourtroomActive(id)`: flip `isActive`, logAudit
- `getAllCourtrooms()`: return all courtrooms ordered by name

### 3.3 — Courtroom management page
- **File:** `app/(dashboard)/registrar/courtrooms/page.tsx`
- shadcn `Table`: Name, Location, Max Slots/Day, Status, Actions
- Create/Edit via `Dialog`
- Deactivate/Reactivate via dropdown menu on each row

### 3.4 — Case validators
- **File:** `lib/validators/case.ts`
- `createCaseSchema`:
  - `defendantName`: string, min 2
  - `defendantAddress`: string, min 5
  - `crimeType`: string, min 2
  - `crimeDate`: date (must be in the past)
  - `crimeLocation`: string, min 2
  - `arrestingOfficer`: string, min 2
  - `arrestDate`: date (must be >= crimeDate)
  - `judgeId`: string (uuid) — must reference a User with role JUDGE
  - `prosecutorId`: string (uuid) — must reference a User with role LAWYER (prosecutors are lawyers in this system)
  - `lawyerId`: string (uuid) — must reference a User with role LAWYER
  - `trialStartDate`: date (must be >= today)
  - `expectedCompletionDate`: date (must be >= trialStartDate)

### 3.5 — Case server actions
- **File:** `actions/case.actions.ts`
- `registerCase(data)`:
  1. Role check (REGISTRAR)
  2. Validate with `createCaseSchema`
  3. Verify judgeId → User.role === JUDGE
  4. Verify prosecutorId, lawyerId → User.role === LAWYER
  5. Insert Case row (CIN auto-generated by Prisma `cuid()`)
  6. `logAudit(actorId, 'CASE_CREATED', 'Case', cin)`
  7. Return `{ success: true, data: { cin } }`
- `getAllCases()`: return cases with judge, prosecutor, lawyer names included (Prisma `include`)

### 3.6 — Case registration page
- **File:** `app/(dashboard)/registrar/cases/new/page.tsx`
- **Single-page form** (NOT a multi-step wizard). Organized into sections with clear headings:
  - **Defendant Information** — name, address
  - **Crime Details** — type, date, location, arresting officer, arrest date
  - **Assigned Personnel** — Judge (dropdown of active JUDGEs), Prosecutor (dropdown of active LAWYERs), Defense Lawyer (dropdown of active LAWYERs)
  - **Trial Schedule** — start date, expected completion date
- Dropdowns populated server-side (fetch active users by role)
- On success: toast with generated CIN, option to go to case list or register another
- On error: inline field-level errors

### 3.7 — Case list page
- **File:** `app/(dashboard)/registrar/cases/page.tsx`
- shadcn `Table` — columns: CIN, Defendant, Crime Type, Status, Judge, Start Date
- CIN column uses monospaced font (`font-mono text-sm`)
- Status shown as a muted badge — same color family, differentiated by weight:
  - REGISTERED: muted gray
  - PENDING: foreground/normal weight
  - ADJOURNED: italic or lighter
  - RESOLVED: foreground with a subtle checkmark icon
  - CLOSED: muted, slightly faded
- Clickable rows → navigate to `/registrar/cases/[cin]`
- Sortable by CIN (default)
- "Register New Case" button top-right

### 3.8 — CIN badge component
- **File:** `components/shared/cin-badge.tsx`
- Renders CIN in `font-mono text-sm bg-muted px-2 py-0.5 rounded-sm`
- Reusable anywhere a CIN needs to be displayed

## Design notes

- Case registration form: two-column layout on desktop (defendant info left, crime details right), single column on mobile. Personnel section full-width below. Dates in a row.
- Case list: dense table. No card view option. This is a records system, not a Kanban board.
- Courtroom table: very simple — 4 columns, no expand/collapse. Government register aesthetic.

## How to verify

- Create 2–3 courtrooms (different max slots)
- Register 3 cases with different judges/lawyers
- Each case gets a unique CIN
- Cases appear in the list table, sorted by CIN
- CIN is rendered in monospace
- Check Prisma Studio → Case rows exist + AuditLog rows for each creation
- Try registering a case with a Lawyer as judge → rejected (role validation)
